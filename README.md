# Stool Group / Moderli — дилерская программа

Адаптивный лендинг на русском языке с тремя форматами сотрудничества, анкетой и серверной отправкой писем через SMTP или Resend. Страница и шрифты работают без сторонних CDN. Сборка не нужна; для SMTP используется Nodemailer из зафиксированного lockfile.

## Запуск

Нужен **Node.js 24.5 или новее**. Проверено на 24.19.0.

```sh
cd /workspace/dealerlanding
npm ci
npm start
```

Сервер слушает порт `3000` на `0.0.0.0`; `PORT` и `HOST` можно переопределить. Для разработки с перезапуском серверного кода — `npm run dev`. Статические файлы перечитываются при каждом запросе. Локальная проверка:

```sh
curl --fail http://127.0.0.1:3000/api/health
```

`mailConfigured: false` означает, что страница доступна, но отправка писем не настроена. Это не тест доставки.

## Подключение почты Mail.ru

В защищённых настройках сервера задайте:

| Переменная | Значение |
| --- | --- |
| `MAIL_TRANSPORT` | `smtp` |
| `SMTP_HOST` | `smtp.mail.ru` |
| `SMTP_PORT` | `465` — TLS с начала соединения; либо `587` — обязательный STARTTLS |
| `SMTP_USER` | Полный адрес действующего почтового ящика, например `petrochenko_s@stoolgroup.ru` |
| `SMTP_PASSWORD` | Пароль приложения для этого ящика, полученный у администратора или в настройках безопасности почты |
| `MAIL_FROM` | Имя и адрес отправителя, разрешённого этому ящику, например `Stool Group / Moderli <petrochenko_s@stoolgroup.ru>` |

Пароль вводится **только в защищённые настройки**. В этой облачной платформе нужен прямой ввод переменной `SMTP_PASSWORD`, сохранённой как секретное значение; подстановка секрета в HTTPS-прокси не подходит для SMTP-аутентификации. Не присылайте пароль в чат. Для локального запуска можно скопировать `.env.example` в `.env` и заполнить значения. `.env` исключён из Git. Не добавляйте секреты в `public/`, клиентский JavaScript, команды или логи.

После изменения настроек перезапустите приложение и проверьте:

```sh
npm run mail:check
```

Команда проверяет TLS-соединение и аутентификацию SMTP, **не отправляя писем**. Даже успешная аутентификация не доказывает разрешение конкретного адреса отправителя и доставку во входящие. Для полной проверки нужна отдельно согласованная контрольная заявка с проверкой обоих почтовых ящиков. `/api/health` возвращает только наличие необходимых настроек: `mailConfigured: true` не означает, что SMTP-сервер доступен или принял пароль.

### Ограничение текущей облачной среды

Для SMTP сервер размещения должен разрешать исходящее TCP-соединение на `smtp.mail.ru:465` (либо `587`). В текущей облачной среде разрешён HTTP/HTTPS, но нет настроенного исходящего SMTP-маршрута: TCP-прокси `proxy:8088` при проверке недоступен. Открытый доступ к HTTP/HTTPS не даёт доступ к SMTP. Письма через Mail.ru из этой среды **не проверены**. Для запуска нужен Node-хостинг / сервер компании с исходящим SMTP или поддержка такого подключения платформой. Не обходите сетевые ограничения и не отключайте проверку TLS.

Для обычной отправки от существующего корпоративного ящика через Mail.ru не требуется создавать аккаунт Resend. Право отправки от `MAIL_FROM` и ограничения автоматических писем подтверждает администратор почты.

### Альтернатива: Resend

Существующее подключение Resend сохранено: `MAIL_TRANSPORT=resend`, `RESEND_API_KEY` и `MAIL_FROM` с подтверждённым в Resend доменом. Если транспорт не задан, применяется совместимое поведение Resend. При явном выборе SMTP приложение не переключается на другой сервис при ошибке. Для Resend нужен HTTPS-доступ к `api.resend.com`. `npm start` и `npm run dev` используют `--use-env-proxy` для штатных HTTP-прокси и инъекции учётных данных; этот флаг не создаёт SMTP-маршрут. TLS-проверка остаётся включена.

### Что отправляется

Получатель анкет фиксирован: **petrochenko_s@stoolgroup.ru**. В письмо входят выбранный формат, данные компании, контакты, реквизиты, комментарий и вложения. Клиент получает полное КП с условиями всех трёх форматов, прайсами, логистикой и контактами. Успех показывается после принятия обоих писем почтовым сервером / API; фактическое попадание во входящие зависит от почтового провайдера. При частичной отправке форма сообщает, какое письмо не удалось передать.

Resend использует ключи идемпотентности провайдера. Для SMTP повтор в пределах одного процесса временно запоминает уже принятый этап, чтобы не отправлять письмо Семёну повторно при сбое письма клиенту. Состояние ограничено по сроку и количеству, содержит хеши и этапы без анкеты. После перезапуска процесса и при неоднозначном сетевом обрыве возможны повторы; SMTP не даёт гарантии единственной доставки.

## Что проверяет анкета

- Все форматы: компания, город, имя, телефон, email, согласие с условиями и на обработку данных. Реквизиты — текстом от 10 символов либо отдельным файлом.
- Интернет-магазин: ссылка на сайт и подтверждение размещения от 100 SKU.
- Салон / шоурум: адрес и минимум две фотографии, подтверждение экспозиции от 5 разных моделей.
- Проектная организация: подтверждение условий с ориентиром от 300 000 ₽ в квартал; цена «Действующая опт + 10%».
- Файлы: одна карточка компании и до четырёх фотографий; PDF/JPG/PNG/WebP, до 2 МБ каждый, до 7 МБ суммарно. Сервер проверяет сигнатуру содержимого. Для фотографий PDF недопустим.

Реквизиты и фотографии не сохраняются в базе или на диске сервера; они передаются почтовому провайдеру и получателю. Не добавляйте логирование тела заявок. В окне согласия указан фактический способ обработки; перед публичным запуском владельцу сайта нужно дополнить документы юридическими реквизитами оператора и согласовать использование выбранного почтового сервиса.

## Проверки

```sh
npm test
node --check public/app.js
```

Автоматические тесты используют встроенный `node:test`, подмену почтовых транспортов и локальный SMTP-сервер; реальные письма не отправляются. Проверяются заявка и КП, форматы, реквизиты и фотографии, ошибки провайдера, отсутствие настроек, ограничения файлов и запросов, защита статических файлов и заголовки безопасности. Для тестов нужны локальные TCP-соединения.

Функциональная проверка в браузере: выбрать каждый формат, проверить цену и обязательные поля, добавить/удалить вложения, отправить корректную анкету. Без почтовой конфигурации должна появиться честная ошибка, а не подтверждение отправки. На мобильном устройстве проверить меню, поля и отсутствие горизонтальной прокрутки.

## Размещение

Запускайте `npm start` под менеджером процессов или на Node-хостинге за HTTPS. Живой процесс не переносится в снимок облачной среды — его нужно запускать заново. Для будущих задач используйте существующий checkout; отдельный Git worktree не требуется.

Встроенный лимит — 10 попыток за 15 минут на адрес сокета. За обратным прокси адрес может быть общим для посетителей: перед публичным запуском настройте ограничение на стороне доверенного прокси / платформы. Сервер намеренно не доверяет произвольному `X-Forwarded-For`.

## Файлы

- `public/index.html`, `styles.css`, `app.js` — интерфейс.
- `server.mjs` — статический сервер, проверка анкеты, отправка через SMTP / Resend.
- `test/server.test.mjs` — серверные тесты.
- `public/assets/interior.png` — сгенерированная интерьерная иллюстрация, не фотография конкретных товаров бренда. При необходимости замените на согласованный снимок продукции.
- `public/assets/golos-*.woff2` — локальный Golos Text, лицензия SIL OFL в `Golos-Text-LICENSE.txt`.

Цены и остатки открываются по исходной ссылке из КП. Текст КП находится в константе `OFFER` в `server.mjs`.
